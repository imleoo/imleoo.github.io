# 我试了把Vibe Coding，结果被AI实习生气笑了

原稿写了一个很完整的 Vibe Coding 实验：语音生成 Chrome 插件、SQL 注入测试、五个工具写购物车、凌晨三点改活动页。问题是，这些实验没有留下工具名称、提示词、代码、截图或测试结果，文中还有乱码。它不像测试记录，像 AI 照着「先翻车、后真香」编的段子。

所以这些亲历全部撤掉。

Vibe Coding 真正容易让人上头的地方，是反馈太快。说一句需求，页面出来了；再说一句，按钮会动了。以前写半天才能看见的东西，现在几分钟就有个样子。做原型和一次性小工具，这种速度确实舒服。

麻烦也藏在这个速度里。页面亮起来以后，人很容易把「看见结果」误认成「完成开发」。至于输入是否合法、权限有没有越界、异常怎么处理、依赖能不能升级，只要演示时没炸，就先当不存在。

AI 像不像实习生不重要。实习生至少知道自己要接受代码审查，AI 生成的代码却经常披着「工具输出」的外衣直接进项目。工具不会对上线结果负责，最后签字的还是人。

要判断一段 AI 代码能不能留，我现在只看几件事：能不能解释，能不能测试，失败时影响多大，出了问题能不能回滚。四个问题答不上来，生成得再快也只是原型。

Vibe Coding 可以用，别拿「氛围」当验收标准。按钮闪不闪粉无所谓，代码进生产之前，测试必须亮绿灯。
